# ChatGPT Conversation Extractor

[English version](README.md)

Небольшой браузерный userscript для локального экспорта текущей активной ветки разговора ChatGPT. Он не использует Ctrl+A / Ctrl+C, не собирает переписку из DOM страницы, не прокручивает чат и не создаёт Print/PDF.

[Скачать userscript](https://github.com/2015pulsar/chatgpt-conversation-extractor/releases/download/v0.2.0/chatgpt-conversation-extractor.user.js)

[Открыть pre-release v0.2.0](https://github.com/2015pulsar/chatgpt-conversation-extractor/releases/tag/v0.2.0)

Некоторые пользователи очень длинных разговоров ChatGPT сообщают о неполном копировании и других проблемах при работе с большими чатами. Этот проект — практический обходной инструмент для тех, кому нужна структурированная локальная копия одного открытого разговора.

> **Неофициальный проект:** проект не связан с OpenAI и не одобрен OpenAI. Он использует внутренние недокументированные web-endpoints ChatGPT, которые могут измениться в любое время.

- Версия: **0.2.0, публичный pre-release**
- Последняя проверка: **2026-08-09**
- Область работы: один разговор, открытый на `https://chatgpt.com/`

## Какие файлы создаются

При успешной проверке скачиваются три файла, построенные из одного snapshot conversation JSON.

### Markdown (`.md`)

Читаемая человеком текущая активная ветка. В ней находятся:

- видимые сообщения пользователя;
- видимые ответы Assistant;
- время сообщения, если оно присутствовало;
- имена вложений рядом с тем сообщением, к которому они относились.

System, tool, внутренние routing-сообщения, thoughts, reasoning recap и context nodes намеренно не включаются.

### Исходный JSON (`.json`)

Неизменённый conversation JSON, который вернул ChatGPT. В нём может быть заметно больше информации, чем в Markdown:

- дерево разговора и `mapping`;
- `current_node`;
- идентификаторы сообщений и связи parent/child;
- timestamps и metadata;
- имена, ID и MIME-информация вложений;
- reasoning-related recap или metadata, фактически возвращённые ChatGPT;
- внутренние tool calls и tool results, включая результаты поиска и обработки файлов;
- фрагменты текста, если ChatGPT ранее загрузил их в tool result;
- другая metadata, фактически возвращённая backend.

JSON **не является резервной копией оригинальных загруженных файлов**. Изображения, ZIP и другие бинарные вложения не помещаются внутрь JSON только потому, что они были прикреплены к чату. В JSON могут встретиться reasoning-related metadata, recap или internal nodes, возвращённые ChatGPT, но проект не обещает и не рекламирует выгрузку скрытой приватной chain of thought.

> **Предупреждение о приватности:** raw JSON может содержать значительно больше внутренней информации, чем Markdown. Обязательно просмотрите его перед публикацией или передачей другим людям.

### Отчёт целостности (`.integrity.txt`)

Это техническая структурная проверка, а не ещё одна копия переписки. Отчёт содержит, например:

- количество nodes в `mapping`;
- количество nodes в активной ветке;
- число видимых User и Assistant messages;
- количество найденных вложений;
- broken parent links;
- cycles и duplicate node visits;
- итоговый `PASS` или `FAIL`.

Число ответов Assistant не обязано совпадать с числом сообщений пользователя. Один пользовательский запрос иногда создаёт несколько видимых Assistant-сообщений или статусных сообщений.

## Установка для новичка

Основной и фактически проверенный способ установки — **Violentmonkey**. Текущий pre-release физически проверен на Windows desktop в сочетаниях **Firefox + Violentmonkey** и **Chrome + Violentmonkey**. Violentmonkey — это расширение браузера, которое позволяет запускать небольшие пользовательские скрипты на выбранных сайтах.

1. Установите Violentmonkey из официального магазина расширений браузера.
2. Откройте Violentmonkey.
3. Создайте новый userscript.
4. Полностью удалите стандартный шаблон.
5. Откройте файл `dist/chatgpt-conversation-extractor.user.js` из папки проекта.
6. Скопируйте файл целиком, включая заголовок userscript.
7. Вставьте его в редактор Violentmonkey.
8. Сохраните userscript.
9. Убедитесь, что тумблер скрипта включён.
10. Откройте или обновите страницу конкретного разговора ChatGPT.
11. Найдите кнопку **Export chat** слева от строки ввода сообщения.

Если вы включили или выключили скрипт тумблером Violentmonkey, обновите страницу ChatGPT. Уже открытая страница не обязана мгновенно загрузить или выгрузить userscript.

### Обязательное разрешение в Chrome

Chrome требует дополнительного разрешения, прежде чем Violentmonkey сможет запускать userscripts:

1. Откройте `chrome://extensions`.
2. Найдите **Violentmonkey** и откройте **Сведения / Details**.
3. Включите **Разрешить пользовательские скрипты / Allow User Scripts**.
4. Обновите страницу ChatGPT.

Если разрешение выключено, Chrome может показывать установленный скрипт зачёркнутым в Violentmonkey, а кнопка **Export chat** не появится.

Если при установке Violentmonkey сообщает о конфликте name/namespace, значит другая копия ChatGPT Conversation Extractor уже установлена. Удалите дубликат или обновите существующий установленный скрипт вместо создания второй копии.

Tampermonkey предположительно совместим со стандартной userscript metadata и браузерными API проекта, но владелец физически его не проверял.

Никогда не вставляйте вручную access token или cookies ChatGPT в userscript. Скрипт использует уже авторизованную вкладку ChatGPT.

## Использование

1. Откройте разговор ChatGPT, который хотите сохранить.
2. Нажмите **Export chat**.
3. Дождитесь `PASS` или `FAIL` в панели результата.
4. Браузер скачает доступные файлы и при необходимости попросит разрешить несколько загрузок.
5. Нажмите **Hide result**, чтобы закрыть панель.
6. Для нового актуального snapshot снова нажмите **Export chat** — перезагрузка страницы не нужна.

При structural `PASS` скачиваются Markdown, raw JSON и integrity report. При structural `FAIL` действует принцип fail closed: raw JSON и технический отчёт остаются доступными, но Markdown не создаётся, чтобы частичная ветка не выглядела полной.

## Как это устроено

- Conversation ID берётся из текущего URL `/c/<conversation-id>`.
- Используется существующая авторизованная сессия на точном origin `chatgpt.com`.
- Conversation JSON запрашивается один раз.
- Текущая ветка строится по цепочке `current_node -> parent -> root` и разворачивается.
- Проверяются missing parents, cycles и повторные посещения nodes.
- Все файлы одного экспорта строятся из одного snapshot.

DOM страницы используется только для размещения собственной кнопки и панели относительно composer. Сообщения разговора из DOM не читаются.

## Разработка

Нужен Node.js 18 или новее. Сторонних runtime- и test-зависимостей нет.

```powershell
npm run check
node --check dist/chatgpt-conversation-extractor.user.js
```

Если PowerShell блокирует `npm.ps1`, используйте `npm.cmd run check`.

## Текущие ограничения

- Внутренние endpoints и формат JSON ChatGPT могут измениться без предупреждения.
- Экспортируется один открытый разговор, а не все чаты или весь Project.
- Оригинальные бинарные вложения не скачиваются.
- Team/Business workspace routing не реализован.
- Structural `PASS` подтверждает непрерывность только внутри полученного JSON и ничего не доказывает о других серверных данных.
